=== Stage 8.2 exact diffuse initialization verification ===

Algorithm sourced directly, not from memory of the textbook alone: the
statsmodels 0.14.1 Cython source itself was fetched and read this
session (statsmodels/tsa/statespace/_filters/_univariate_diffuse.pyx.in,
raw GitHub source -- confirmed reachable, unlike most R packages
referenced throughout this project) to resolve the exact branching
logic (F_infty>0 vs F_star>0 cases, the K0/K1/L0/L1 update formulas,
which quantities the diffuse-phase log-likelihood contribution actually
uses) before implementing anything -- this is a case where reading a
mature reference's real, executable source to resolve an ambiguous
textbook description is exactly what this project's own "reference,
never port" policy sanctions (resolve ambiguity, validate numbers,
never copy code) -- and it mattered: the diffuse-phase per-observation
loglikelihood contribution is `-0.5*log(2*pi*F_infty)` ONLY, with NO
`v^2/F` term at all, a detail easy to get wrong from a textbook
description alone.

tolerance_diffuse = 1e-10 confirmed directly from source
(`self.tolerance_diffuse = 1e-10`, hardcoded, `_kalman_filter.pyx.in`
line 385) -- used for both the F_infty/F_star branch decisions and the
collapse-detection check `sum(P_infty**2) > tolerance_diffuse`
(statsmodels' own Frobenius-norm-squared convention, also confirmed
directly from source, line ~1288).

=== Regression / structural guarantees ===

diffuse_idx=Int[] reduces EXACTLY to Stage 8.1's kalman_filter(
::TimeVaryingSSM,...): loglik bit-identical (diff=0.0) on
arma11_fit.csv's TimeVaryingSSM (built via to_time_varying); v/F agree
to ~1e-16 (floating-point noise from the different filtering-form vs
prediction-form intermediate factorization -- the same relationship
already proven algebraically in to_time_varying's own docstring for the
Stage 8.1 case, and empirically reconfirmed here for the Stage 8.2
zero-diffuse-dimension case).

Single diffuse state (pure local level, d=1, own synthetic n=30 case):
nobs_diffuse=1, converged, finite loglik -- confirms diffuse_idx of
length 1 works correctly, not just the length-2 case from the primary
verified example.

Mixed proper + diffuse state (one diffuse local level + one KNOWN exact
constant, own synthetic n=20 case): confirms the a0/P_star0 keyword
generalization (beyond the handoff's own minimal proposed signature,
added anticipating Stage 8.3's SARIMAX, which will genuinely need a
mixed proper-ARMA-stationary + diffuse-regression-coefficient state)
works correctly -- nobs_diffuse=1 (only the genuinely diffuse
coordinate contributes to it), converged, finite loglik.

Diffuse phase length is O(d), not O(n) -- confirmed directly by
execution on the SAME 2-diffuse-state structure at n=50/500/5000:
nobs_diffuse=2 in every case, not scaling with n. Timing (excluding
first-call JIT compilation): n=500 -> 0.0017s, n=5000 -> 0.017s --
roughly 10x time for 10x n, consistent with the OVERALL per-step cost
staying O(n) with a fixed O(d) diffuse-specific prefix, exactly as
designed (the diffuse phase is implemented as a short prefix that stops
updating P_infty entirely once it collapses to numerically zero,
falling through to the identical per-step math Stage 8.1's own
kalman_filter already uses, rather than adding diffuse-related
branching to every iteration of the main loop).
