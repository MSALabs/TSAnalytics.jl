=== Stage 8.2 correction: kalman_filter_diffuse's loglik must be the
    full, inclusive sum -- found and fixed during Stage 8.3 ===

Discovered while independently verifying Stage 8.3's model=:tvss against
real Python SARIMAX(time_varying_regression=True, mle_regression=False,
use_exact_diffuse=True): fitting at Python's own reported optimum
parameter values, Julia's kalman_filter_diffuse-based loglik was
systematically off from Python's llf by a small constant (0.0388766,
identical across two different parameter settings -- not optimizer
noise, which would not repeat identically).

Root cause: Stage 8.2's kalman_filter_diffuse excluded the first
`nobs_diffuse` observations' likelihood contributions from `loglik`
entirely, modeled on this project's `nobs = n - d` differencing
convention (Stage 6.6/6.7). That convention does not apply to exact
diffuse initialization.

Direct confirmation via real statsmodels:

  from statsmodels.tsa.statespace.sarimax import SARIMAX
  mod = SARIMAX(y, exog=x, order=(1,0,0), trend='n',
                time_varying_regression=True, mle_regression=False,
                use_exact_diffuse=True)
  res = mod.filter([0.47465807, 0.0, 0.98227306])
  res.llf                    # -213.76718527012832
  mod.ssm.loglikelihood_burn # 0   <-- NOT nobs_diffuse (=1 here)
  res.filter_results.llf_obs[0]  # -0.03887658  (finite, well-defined,
                                  #  INCLUDED in res.llf)

  -0.5*(log(2*pi) + log(Finf_1)) = -0.03887658  where Finf_1 = x_1^2
  (x_1 = -0.41475721, the exog value at t=1) -- confirms the diffuse-
  phase per-observation formula itself (`-0.5*log(2*pi*F_infty)`, no
  v^2/F term) was already correctly identified in Stage 8.2's own
  docstring; the bug was excluding it from the sum, not the formula.

Re-checked against Stage 8.2's OWN original worked example
(test/verification/diffuseinit/diffuse_case1.csv,
diffuse_case1.json) -- generated by
test/verification/diffuseinit/gen_diffuse_case1.py, which had ALREADY
captured both quantities side by side from the very first run, but only
the wrong one was checked at the time:

  loglik_full        (= res.llf, statsmodels' genuine default) = -14.53870388541507
  loglik_excl_diffuse (manually np.sum(llf_obs[nobs_diffuse:]))  = -11.239210224444564

test/test_diffuseinit.jl's first testset asserted the latter
(-11.239210224444564) as if it were kalman_filter_diffuse's own
`loglik`. Fixed: kalman_filter_diffuse now accumulates the diffuse-phase
term (`log(Finf_t)`, no v^2/F) into the same running sum as the
ordinary-phase term, and divides by `n` (not `n - nobs_diffuse`) in the
final `-0.5*(n*log(2*pi) + acc)` formula -- test updated to assert
-14.53870388541507 instead. `nobs_diffuse` itself is unchanged and still
returned (useful diagnostic: how many leading observations were
diffuse-influenced), it simply no longer changes what `loglik` sums.

Julia (after fix) on diffuse_case1.csv, diffuse_idx=[1,2]:
  loglik = -14.538703885415... -- matches res.llf to ~1e-11
  nobs_diffuse = 2               -- unchanged, still correct

Julia (after fix) on Stage 8.3's own sarimax_exog_shared.csv system
(AR(1) companion block + 1 diffuse beta state), evaluated at Python's
own fitted params in both the free- and fixed-Q_beta cases:
  free Q_beta:  loglik = -213.74793442... vs Python llf -213.74793442697535
  Q_beta=[0.0]: loglik = -213.76718527... vs Python llf -213.76718527012832
Both now match to ~1e-7 or better (Julia's own subsequent joint
re-optimization from these matches independently to similar precision).

Downstream impact: Stage 8.3's model=:tvss AIC/BIC no longer needs (and
does not use) an `nd - nobs_diffuse`-adjusted observation count for
loglik itself -- `nobs_diffuse` is kept only as informational metadata
on ArimaxModel/SarimaxModel, matching what it always was: a diagnostic,
not a normalization.
