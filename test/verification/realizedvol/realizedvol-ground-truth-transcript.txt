Exact formulas confirmed by reading real, executed R source directly
(not transcribed from documentation):

1. RV (rRVar): rv <- colSums(q^2)  -- exactly sum(r_i^2), as expected.

2. BV (RBPVar, what rBPCov actually calls for a univariate series):
   rbpvar <- (pi/2) * sum(abs(returns[1:(n-1)]) * abs(returns[2:n]))
   -- CONFIRMED: NO N/(N-2) finite-sample correction factor, contrary
   to the handoff's own formula box (which included one). This is a
   real discrepancy between the handoff's citation and the actual
   executable reference -- resolved in favor of the real source, since
   this session can now execute it directly. Some published
   presentations of BV do include N/(N-2); highfrequency's own actual
   code doesn't.

3. TQ (rTPQuar): confirmed exactly matching the handoff's own framing
   (which didn't give the formula explicitly, just said "needed"):
     q <- rollApplyProdWrapper(abs(returns), 3)   # rolling triple product
     N <- nrow(q) + 2
     TQ <- N * (N/(N-2)) * (gamma(0.5)/(2^(2/3)*gamma(7/6)))^3 * sum(q^(4/3))
   mu_{4/3}^{-3} = (gamma(0.5)/(2^(2/3)*gamma(7/6)))^3 -- computed via
   this project's own _loggamma (already used for diagnostics.jl's
   chi-squared machinery), not a new SpecialFunctions.jl dependency.

4. Jump test (BNSjumpTest, type="ratio"): confirmed exactly:
     theta <- switch(IVestimator, BV = pi^2/4 + pi - 3, ...)
     a <- sqrt(N) * (1 - hatIV/RV) / sqrt((theta-2) * product)
   where product = max(1, IQ/IV^2) ONLY when max=TRUE is explicitly
   passed -- highfrequency's own DEFAULT is max=FALSE (product =
   IQ/IV^2 alone, no floor). This project deliberately uses the
   max=TRUE variant (documented explicitly in jump_test's own
   docstring as a deliberate divergence from the reference's default,
   not an oversight) -- it's the more robust, more commonly cited form
   in the jump-test literature. theta-2 = pi^2/4 + pi - 5, confirmed
   algebraically identical to the handoff's own transcribed
   "(pi/2)^2 + pi - 5" (matches exactly, since (pi/2)^2 = pi^2/4).

5. Semivariance (rSVar): confirmed exactly:
     rSVard <- colSums((q * (rData<0))^2)   # negative-return contributions
     rSVaru <- colSums((q * (rData>0))^2)   # positive-return contributions
