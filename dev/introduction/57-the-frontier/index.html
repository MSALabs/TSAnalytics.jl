The Frontier

Fifty-six chapters in, it is worth being precise about where this package stops. Not because the gaps are embarrassing — every library has them — but because knowing which wall you are standing at tells you which direction to walk.

This chapter is a map of what is missing, why, and what you would use instead today.

The shape of what exists

Everything in this book reduces to a small number of things:

  • a Kalman filter on a Gaussian state-space model, which ARMA, ARIMA, SARIMA, ARIMAX and drifting-coefficient regression all compile down to;
  • an innovations recursion for exponential smoothing, in which the initial states are estimated as parameters, so that ETS, Theta and TBATS need no diffuse initialisation at all;
  • a conditional-variance recursion, which GARCH, GJR and EGARCH share;
  • multivariate least squares and reduced-rank regression, on which the VAR, the Johansen test and the VECM all stand;
  • a sequential multivariate Kalman filter, which unobserved components and dynamic factor models compile down to — the same state-space engine, now taking a matrix of series;
  • a filter over a discrete hidden state — Hamilton's — for Markov-switching models, and a least-squares search over a threshold for the threshold autoregressions;
  • a set of decomposition procedures — classical, STL, MSTL — that do not involve a likelihood at all;
  • and diagnostics, which are independent of all of the above and will happily test residuals you produced some other way.

That shape is the reason the gaps are where they are. Anything that fits one of those forms is comparatively cheap to add; anything that does not needs new machinery.

Series that move together: what is still missing

This section used to say that everything here was univariate. It no longer is. Part X builds the multivariate track from the VAR (Chapter 45) through Granger causality, impulse responses, the three cointegration tests, the VECM and structural identification (Chapter 51), each number checked against R's vars and urca and against statsmodels.

Exponential smoothing: the other fifteen

Part V teaches the fifteen ETS forms that exist — R's whole default search space — together with Theta and TBATS. The fifteen that remain are the multiplicative-trend forms, which R also excludes by default because they are unstable, and the ETS(A,·,M) trio, which R refuses outright because the level update divides an additive error by a seasonal factor. A reader who wants a multiplicative trend should be told plainly that no mainstream package offers one by default either.

TBATS is built without the automatic search R's tbats() wraps around it and without ARMA errors; both are additions on top of what exists, not changes to it.

Components you can name: what is still missing

This section used to say that unobserved components models were the obvious state-space application not yet built. They are built now — Chapter 52 and Chapter 53: a level, a slope, a seasonal, a cycle and an autoregressive part, each with its own variance, fitted jointly, every component returned with a standard error — and so are dynamic factor models (Chapter 54), the same idea across many series at once.

What they do not yet have:

  • Drifting regression coefficients inside a UC model. Regressors enter fit_uc with fixed coefficients; a coefficient that is itself a random walk is still fit_arimax(…; model=:tvss), in Chapter 39.
  • Exact diffuse initialisation for UC. The non-stationary components start from a large-variance prior, as statsmodels does, and the periods it consumes are left out of the likelihood and reported without a standard error rather than with a meaningless one.
  • Forecast intervals that account for estimated variances — the same limitation every reference shares.

Regimes: what is still missing

The model can change now. Markov-switching regressions and autoregressions (Chapter 55) let the parameters jump between unobserved states, with fixed or covariate-driven transition probabilities; threshold autoregressions (Chapter 56) let them change when an observed lag crosses a boundary, abruptly or smoothly, and setar_test asks whether a threshold is there at all. Each is checked against R's MSwM or tsDyn and statsmodels, and in several places goes further than both — a three-regime phase plot, a threshold profile for any criterion, a count of how many optima the restarts found.

Distributions other than the normal

GARCH is no longer Gaussian-only: fit_garch(...; dist=:t) estimates a Student-t shape alongside the variance recursion, and it agrees with Python's arch and R's rugarch. What remains Gaussian is everything else. Every forecast interval in this package — ARIMA, ETS, VAR — is a normal interval around the point forecast, and jarque_bera_test and normality_test are in the checklist precisely because you should know when that assumption is doing work it cannot support.

The neighbouring package

Official seasonal adjustment — X-11's lineage, X-13ARIMA-SEATS, the diagnostics statistical agencies publish — is deliberately not here. It is a different package, SeasonalAdjustment.jl, for the reasons Part IX sets out: it is a different kind of activity, with institutional requirements that have no analogue in exploratory modelling.

The boundary is clean. stl_decompose is how you decompose a series. X-13 is how a statistical office publishes one.

What will not change

Some things are not gaps, and will not be filled:

No container integration. No dependency on TSFrames, TimeSeries or DataFrames, ever. Every function here accepts anything the tsvalues/tsindex interface can be called on, which by default means any iterable — and, for the multivariate functions, anything tsmatrix can turn into a matrix, including a NamedTuple of columns. Adding a container dependency would buy convenience for one community at the cost of everyone else's.

No ported code. Every algorithm here is implemented from its primary source. R and Python are used to resolve ambiguity when a paper underspecifies something, and to validate output numbers — never to translate from. That is slower, and it is the reason the divergences documented throughout this book are decisions rather than accidents.

No silent fallbacks. pacf(method=:mle) errors rather than quietly using Yule-Walker — which is what R does. forecast_volatility(egarch_model, 5; method=:analytic) errors rather than quietly simulating. pvalue on a Phillips-Ouliaris test errors, because the paper tabulates critical values and no p-values, rather than inventing one by interpolation. A wrong number you trust is worse than an error you can read.

Where to start

If you want to contribute, the ordering that makes sense is roughly the order of this chapter. Bands for structural impulse responses and the restricted-β tests complete the multivariate track that Part X opened; a confidence set for the threshold, and the break tests that date a change rather than only detect it, complete the regime models.

development-sequence.md in the repository carries the full staged roadmap with dependencies — what is built, what is next, and what each piece needs before it can start.
