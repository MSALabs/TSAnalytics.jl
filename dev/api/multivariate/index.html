Vector time series. See the manual chapter Vector Autoregression for the narrative, including the places where the two references disagree with each other.

Vector autoregression

TSAnalytics.fit_var — Function
fit_var(Y, p; deterministic=:const, method=:qr) -> VARModel

Fit a vector autoregression of order p by least squares.

Y is anything tsmatrix accepts — a matrix with rows = time and columns = variables, a NamedTuple of columns (so fit_var(dataset("econ5"), 2) works directly), or a collection of column vectors. Variable names come from tsnames when the container carries them.

y_t = ν + Π t + A₁ y_{t-1} + … + A_p y_{t-p} + u_t

deterministic selects the deterministic terms and spans both references' vocabularies, which are mutually incomplete; see _var_ndet's table. The spelling is deliberately neither R's type= nor statsmodels' trend=, because both are ambiguous: R's type="trend" means a trend with no constant, while statsmodels' trend="ct" means constant and trend, and they differ by 6.15 in log-likelihood on the bundled fixture.

What it refuses

Both references silently accept several inputs that cannot produce a meaningful fit. [V] n = 8, K = 2, p = 5 — eleven parameters per equation from three observations — returns without complaint from both. This refuses, by name:

  • K = 1. Both references refuse this too, and the univariate path is far better served by arx or fit_arima.
  • p < 1. [V] R errors obscurely (length of 'dimnames' [2] not equal to array extent); statsmodels does not error at all.
  • p too large for the sample.
  • NaN in the input. [V] R says NAs in y.; statsmodels raises LinAlgError: SVD did not converge and LAPACK writes to stderr.
  • An unrecognised deterministic.

Out of scope, stated rather than hidden

Exogenous regressors (vars::VAR(exogen=), statsmodels VAR(exog=)), restricted VARs (vars::restrict) and Bayesian shrinkage priors are not implemented. The regressor construction here would carry exogenous columns untouched, so it is a clean later addition rather than a rewrite.

julia> using TSAnalytics, DelimitedFiles

julia> Y = readdlm(joinpath(dirname(pathof(TSAnalytics)), "..", "test",
                            "fixtures", "var", "var2_p1.csv"), ','; skipstart=1);

julia> m = fit_var(Y, 1);

julia> size(m.A[1])
(2, 2)

julia> round(m.loglik, digits=6)               # vars::logLik: -500.83136
-500.83136

julia> is_stable(m)
true

See also var_select, roots, forecast.

TSAnalytics.VARModel — Type
VARModel <: TimeSeriesModel

A fitted vector autoregression, returned by fit_var.

Fields

  • Y: the data, n × K, rows = time, columns = variables.
  • names: the K variable names, [:y1, …] when the input carried none.
  • p: the lag order; deterministic: which deterministic terms were included.
  • A: p matrices, each K × K. A[j][i, m] is the coefficient on variable m at lag j in equation i — so A[j] is directly the matrix the companion form and the impulse-response recursion want.
  • det_coef: K × ndet, columns in the order (const, trend, trend²).
  • sigma_df: E'E / (T - Kp - ndet), the degrees-of-freedom-adjusted residual covariance — this feeds standard errors and forecast intervals.
  • sigma_mle: E'E / T — this feeds the log-likelihood and the information criteria. Both are stored because both references report both and they are not interchangeable.
  • se: K × (Kp + ndet), laid out like coef(m).
  • vcov_full: K(Kp+ndet) × K(Kp+ndet), kron(sigma_df, (Z'Z)⁻¹), kept whole rather than as a diagonal because the analytic impulse-response standard errors consume the whole thing.
  • resid, fitted: T × K.
  • loglik, T (effective observations, n - p).
  • C: the Kp × Kp companion matrix, built once at fit time and cached, because roots, the impulse-response recursion and the structural decomposition all want it.
  • converged: always true — this is OLS, and the field exists for contract uniformity.

Coefficient layout

Neither reference's flat layout is used. vars returns K × (Kp + ndet) with the deterministic terms last; statsmodels returns (ndet + Kp) × K with them first, transposed. Both were verified to agree with each other once reordered (maximum absolute difference 2.5e-16 at K = 2), so there is no right answer to inherit — and separating A from det_coef removes the ordering question from every model built on top of this one.

TSAnalytics.var_select — Function
var_select(Y; lag_max=10, deterministic=:const, parallel=true) -> VARSelection

Fit every VAR order from 1 to lag_max and report the four information criteria, with the lag each one selects.

The sample is held fixed, and that is the whole subtlety

[V] Both vars::VARselect and statsmodels' select_order estimate every candidate p on the same T = n - lag_max observations, so the criteria are comparable across p. A single fit_var(Y, p) uses all n - p observations available to it, which is more. On var2_p1.csv with lag_max = 8:

var_select(Y; lag_max=8).aic[1]   = -0.6050354269   (T = 192)
aic(fit_var(Y, 1))                = -0.5819716232   (T = 199)

Neither is wrong and both references report both, so this is a difference to understand rather than a bug to find. If you want the selection figure for one order, slice the data yourself: aic(fit_var(Y[lag_max - p + 1:end, :], p)) reproduces it exactly.

[V] Note also that statsmodels' select_order(L) returns L+1 values, for lags 0…L, where vars::VARselect(lag.max=L) returns L, for lags 1…L. This returns 1…lag_max, matching R; a lag-0 model is not a VAR.

The candidates are independent fits, so they run on threads when Julia has more than one. The parallel and serial paths select the identical model, not merely an equally good one, which the test suite asserts.

julia> using TSAnalytics, DelimitedFiles

julia> Y = readdlm(joinpath(dirname(pathof(TSAnalytics)), "..", "test",
                            "fixtures", "var", "var3_p2.csv"), ','; skipstart=1);

julia> s = var_select(Y; lag_max=8);

julia> s.selected.aic        # the series really is a VAR(2)
2

julia> s.T                   # held fixed at n - lag_max
242

See also fit_var.

Stability

TSAnalytics.roots — Function
roots(m::VARModel) -> Vector{Float64}

The moduli of the companion-matrix eigenvalues, largest first. The process is stable when every one is below 1.

The two references mean different things by `roots`

[V] This is the stage's most dangerous convention trap, because getting it wrong silently inverts a stability test.

vars::roots() returns these companion moduli (stable if < 1). statsmodels' .roots returns the roots of the characteristic polynomial (stable if |·| > 1). They are exact reciprocals — verified on five fixtures with max|R − 1/py| between 1.1e-16 and 9.3e-15.

This package follows R, because "the largest root is 0.97, close to the boundary" is the reading practitioners expect. To compare against statsmodels, take 1 ./ roots(m).

See also is_stable, companion.

companion(m::VARModel) -> Matrix{Float64}

The Kp × Kp companion matrix: the VAR(p) restacked as a VAR(1) on Kp states. Exported because the impulse-response recursion and the structural decomposition both consume it.

On a fitted model this returns the matrix cached at fit time. Given the coefficient matrices directly it builds one. At p = 1 the companion matrix is A[1] — there is no identity block.

Granger causality

TSAnalytics.granger_test — Function
granger_test(m::VARModel; cause, caused=nothing) -> GrangerTest
granger_test(y, x; lags) -> GrangerTest

Granger causality. H0 is that cause does not Granger-cause caused.

These are two different tests, and which you get depends on what you pass. Julia's dispatch is doing real work here rather than overloading a name for convenience.

The system test — granger_test(m::VARModel; cause, caused)

A Wald test on the fitted VAR, restricting every lag of every cause variable in every caused equation to zero. caused defaults to every variable not named in cause.

df1 = p · |cause| · |caused|
df2 = K·T − K·(Kp + ndet)        <- the SYSTEM residual degrees of freedom
F   = Wald / df1

[V] Agrees with vars::causality and statsmodels' test_causality on all 15 reference cases — F to ≤ 7.6e-12, df identically, and p-values to ≤ 7.5e-15 wherever vars does not underflow (see below).

The pairwise test — granger_test(y, x; lags)

A single-equation F test comparing restricted and unrestricted OLS for y on its own lags with and without the lags of x, so df2 is one equation's T − 2·lags − 1. [V] Bit-identical to lmtest::grangertest, and to statsmodels' grangercausalitytests[...]["ssr_ftest"].

When the two coincide, and when they do not

[V] The F statistics are identical when |caused| = 1 — which for the system test's default caused means K = 2 — and differ otherwise. The p-values never coincide, because df2 differs by a factor of K: on var2_p1 at p = 2, 0.4821580341 against 0.4828206979 for the same F of 0.730863702158.

So pick deliberately. The system test is the one to use when a VAR is the model; the pairwise test is what lmtest users will expect.

`vars` reports p = 0 for any moderately strong rejection

[V] vars::causality computes 1 - pf(...) instead of the upper tail, so its p-values underflow to exactly zero in ordinary use — on climhyd an F of 13.36 on (10, 2634) df is reported as 0 against a true 3.66e-23. Four of the fifteen reference cases do this. This package uses _f_ccdf and returns the tail, so its p-values are not comparable with vars there; they agree with statsmodels, which gets it right.

julia> using TSAnalytics, DelimitedFiles

julia> Y = readdlm(joinpath(dirname(pathof(TSAnalytics)), "..", "test",
                            "fixtures", "var", "var2_p1.csv"), ','; skipstart=1);

julia> m = fit_var(Y, 1);

julia> t = granger_test(m; cause = :y1);      # vars: F 17.504579, df (1, 392)

julia> (t.df1, t.df2, t.kind)
(1, 392, :system)

julia> round(statistic(t), digits=6)
17.504579

TSAnalytics.instantaneous_causality — Function
instantaneous_causality(m::VARModel; cause, caused=nothing)
    -> InstantaneousCausalityTest

Test for instantaneous (contemporaneous) causality between cause and caused: a Wald statistic on the off-diagonal block of vech(Σ), asymptotically χ²(|cause| · |caused|).

Cs     = vech(Σ)[idx]
middle = (M[idx, idx])⁻¹ / 2       with M = D⁺ (Σ ⊗ Σ) D⁺'
Wald   = T · Cs' · middle · Cs

D⁺ comes from _dupl_pinv's closed form rather than an SVD, and the selection matrix C is applied by indexing rather than multiplication.

The hypothesis is about contemporaneous correlation, which is symmetric, so this is not a directional statement: swapping cause and caused returns the identical statistic.

This package is the only one that handles the general block case

[V] statsmodels' test_inst_causality raises IndexError whenever both sets have more than one member — var_model.py does sig_mask[causing_ind, caused_ind] = 1 with two fancy index arrays, which only broadcast when one has length 1. Verified failing at (2,4), (3,3) and (4,2) on k = 6, (2,3) on k = 5 and (2,2) on k = 4, and working at (1, k−1) and (k−1, 1). It always errors rather than returning a wrong answer — checked deliberately. The bug reproduces identically on 0.14.1 and 0.15.0.

So vars::causality is the only reference for a general block, and this package agrees with it there.

julia> using TSAnalytics, DelimitedFiles

julia> Y = readdlm(joinpath(dirname(pathof(TSAnalytics)), "..", "test",
                            "fixtures", "var", "var2_p1.csv"), ','; skipstart=1);

julia> t = instantaneous_causality(fit_var(Y, 1); cause = :y2);

julia> t.df
1

julia> round(statistic(t), digits=6)        # vars: 25.783697
25.783697

See also granger_test.

TSAnalytics.GrangerTest — Type
GrangerTest <: HypothesisTest

A Granger causality test. H0 is that cause does not Granger-cause caused.

kind records which test this is, and the distinction is not cosmetic — see granger_test:

  • :system — the VAR-based Wald/F test, vars::causality and statsmodels' test_causality. Its df2 is the system residual degrees of freedom, K·T − K·(Kp + ndet).
  • :pairwise — the single-equation F test, lmtest::grangertest and statsmodels' grangercausalitytests[...]["ssr_ftest"]. Its df2 is one equation's, T − 2·lags − 1.

statistic is the F form and wald the chi-square form, df1 · statistic. Both references report both for the system test, and their p-values differ because one refers to F(df1, df2) and the other to χ²(df1).

TSAnalytics.InstantaneousCausalityTest — Type
InstantaneousCausalityTest <: HypothesisTest

A test for instantaneous causality: H0 is that the residual covariance has no cross-block correlation between cause and caused. A Wald statistic on the off-diagonal block of vech(Σ), asymptotically χ²(|cause| · |caused|).

This says nothing about direction — it is a statement about contemporaneous correlation, which is symmetric — so swapping cause and caused gives the identical statistic, and the test suite asserts that.

Impulse responses and variance decomposition

TSAnalytics.irf — Function
irf(m::VARModel, h; cumulative=false, impulse=nothing, response=nothing,
    stderr=false, boot=false, runs=100, level=95.0,
    rng=Random.default_rng(), parallel=true) -> IRFResult

Impulse responses of a fitted VAR at horizons 0 … h, both orthogonalized (Cholesky) and non-orthogonalized, as an IRFResult.

  • cumulative=true returns running sums Σ_{j≤i} instead.
  • impulse, response select variables by name or index (a single one or a vector); nothing keeps all of them.
  • stderr=true attaches the analytic standard errors of irf_stderr. Point estimates alone are the common case, so they do not pay for a covariance nobody asked for.
  • boot=true attaches residual-bootstrap percentile bands at level percent from runs replications.
Orthogonalized responses depend on the variable order

See orth_ma_rep. Reordering the data's columns changes every orthogonalized response; it is a statement about which shocks move which variables within the period, not a formatting choice. The result's names record the order used.

The bootstrap

Residuals are centred and resampled by row, keeping their contemporaneous correlation; each artificial series is rebuilt through the fitted recursion from the real first p observations, refitted with the same lag order and deterministic terms, and its responses recomputed. That is vars' scheme. The band is the elementwise (1-level/100)/2 and (1+level/100)/2 quantiles across replications.

Each replication draws from its own generator, seeded from rng, so a seeded run is reproducible and the threaded and serial paths return bit-identical bands. runs defaults to vars' 100, which is thin for a 95% percentile interval — 1000 or more is advisable when the band matters.

Bands cannot be checked numerically against vars: a different resampling stream gives different numbers by design. The test suite checks what a band claims instead — that it covers the true response of a known VAR at close to its nominal rate.

julia> using TSAnalytics, DelimitedFiles, Random

julia> Y = readdlm(joinpath(dirname(pathof(TSAnalytics)), "..", "test",
                            "fixtures", "var", "var2_p1.csv"), ','; skipstart=1);

julia> r = irf(fit_var(Y, 2), 8);

julia> r.horizons, round(r.orth[2][1, 1]; digits=10)
(0:8, 0.4716609801)

julia> b = irf(fit_var(Y, 2), 4; boot=true, runs=50, rng=MersenneTwister(1));

julia> b.method, b.runs, size(b.lower[1])
(:bootstrap, 50, (2, 2))

See also fevd, ma_rep, irf_stderr.

irf(m::VECMModel, h; cumulative=false, impulse=nothing, response=nothing) -> IRFResult
fevd(m::VECMModel, h) -> FEVDResult

Impulse responses and variance decomposition of a VECM, computed from its levels VAR (var_rep) by the Stage 10.3 recursion. Point estimates only: the analytic standard errors of 10.3 are for an unrestricted VAR's coefficients, and the VECM's reduced-rank levels coefficients have a different (singular) covariance, so stderr and boot are refused rather than answered with the wrong formula.

Because the levels VAR has unit roots, the responses of a VECM do not die out: they converge to the permanent effect of the shock.

source
irf(s::SVARModel, h; cumulative=false, impulse=nothing, response=nothing) -> IRFResult
fevd(s::SVARModel, h) -> FEVDResult

Structural impulse responses Φ_i P with P = A⁻¹B, and the variance decomposition by structural shock — Stage 10.3's recursion with the structural impact matrix in place of the Cholesky factor, not a second implementation. The result's orth field holds the structural responses and factorization records :structural or :blanchard_quah; nonorth is the reduced form's, unchanged. Point estimates only: the analytic standard errors of irf_stderr are for the Cholesky factor.

For a recursive just-identified model the structural responses equal the orthogonalized ones of irf(s.var, h) up to the sign of each shock.

TSAnalytics.IRFResult — Type
IRFResult

Impulse responses returned by irf. Every matrix is [response, impulse] and every vector of them is horizon first, with horizons == 0:h — so r.orth[1] is the impact response.

  • orth, nonorth: orthogonalized (Cholesky) and non-orthogonalized responses, plain or cumulative as cumulative says.
  • lower, upper: bootstrap percentile bands for orth; lower_nonorth, upper_nonorth the same for nonorth. nothing unless boot=true.
  • stderr_orth, stderr_nonorth: analytic standard errors, nothing unless stderr=true.

  • level, runs: the bootstrap settings; method: :none, :analytic or :bootstrap, so a plot can say what its bands are.
  • factorization: :cholesky, recording how the orthogonalized shocks were identified.

TSAnalytics.ma_rep — Function
ma_rep(m::VARModel, h) -> Vector{Matrix{Float64}}

The first h+1 matrices of the moving-average representation of a fitted VAR, Φ₀ = I and Φ_i = Σ_{j=1}^{min(i,p)} Φ_{i-j} A_j. These are the non-orthogonalized impulse responses: Φ_i[response, impulse] is the response of response i periods after a unit shock to the reduced-form error of impulse.

Returned horizon first, as a vector of K × K matrices, so Φ[i+1] is Φ_i. The two references disagree on every layout while agreeing on every number — vars puts the horizon last in a K × K × (h+1) array, statsmodels first — and when K == h+1 a transposed implementation agrees with a correct one in shape, so the test suite checks this layout on a fixture where that happens.

The order Φ_{i-j} A_j (not A_j Φ_{i-j}) is the one that matches both references, with A_j[i, m] the coefficient of equation i on variable m at lag j. The recursion accumulates into each matrix in place, so it allocates the h+1 result matrices and nothing else.

julia> using TSAnalytics, DelimitedFiles

julia> Y = readdlm(joinpath(dirname(pathof(TSAnalytics)), "..", "test",
                            "fixtures", "var", "var2_p1.csv"), ','; skipstart=1);

julia> m = fit_var(Y, 2);

julia> Phi = ma_rep(m, 8);

julia> length(Phi), Phi[1] == [1.0 0.0; 0.0 1.0], Phi[2] == m.A[1]
(9, true, true)

julia> round(Phi[3][2, 1]; digits=10)    # response of y2 to y1, two periods on
0.1999228499

See also orth_ma_rep, irf.

TSAnalytics.orth_ma_rep — Function
orth_ma_rep(m::VARModel, h) -> Vector{Matrix{Float64}}

The orthogonalized moving-average matrices Ψ_i = Φ_i P, i = 0 … h, where P is the lower-triangular Cholesky factor of the residual covariance (PP' = Σ). Ψ_i[response, impulse] is the response to a one-standard-deviation orthogonalized shock.

The answer depends on the order of the variables

The Cholesky factor makes the first variable contemporaneously affected only by its own shock, the second by the first two, and so on. Reordering the columns of the data is therefore not cosmetic: it changes every orthogonalized response, while the non-orthogonalized ma_rep is merely relabelled. Choosing an order is a claim about contemporaneous causation. The fitted model's names record the order that was used.

julia> using TSAnalytics, DelimitedFiles

julia> Y = readdlm(joinpath(dirname(pathof(TSAnalytics)), "..", "test",
                            "fixtures", "var", "var2_p1.csv"), ','; skipstart=1);

julia> Psi = orth_ma_rep(fit_var(Y, 2), 4);

julia> round.(Psi[1]; digits=10)     # the Cholesky factor itself
2×2 Matrix{Float64}:
 1.00586   0.0
 0.295542  0.731323

See also ma_rep, irf.

TSAnalytics.irf_stderr — Function
irf_stderr(m::VARModel, h; orth=false, cumulative=false) -> Vector{Matrix{Float64}}

Analytic asymptotic standard errors of the impulse responses at horizons 0 … h, horizon first, each K × K and laid out [response, impulse] like ma_rep.

Non-orthogonalized (Lütkepohl 2005, Prop. 3.6): cov(vec Φ_i) = G_i Σ_α G_i', with Σ_α the covariance of coef_alpha. Orthogonalized: cov(vec Ψ_i) = C_i Σ_α C_i' + C̄_i Σ_σ C̄_i' with C_i = (P' ⊗ I) G_i, C̄_i = (I ⊗ Φ_i) H, Σ_σ the covariance of vech Σ̂ and H the derivative of the Cholesky factor. cumulative=true gives the standard errors of the running sums Σ_{j≤i} Φ_j (or Ψ_j), whose derivatives are the running sums of the same matrices.

Two things worth knowing

The orthogonalized formula is verified by simulation, not by the book. statsmodels' own source marks the textbook statement as wrong at this equation. The version implemented here was checked two independent ways in the Stage 10 handoff: a central-difference Jacobian of the recursion (agreement ≤ 2.1e-12), and a 4000-replication parametric bootstrap of the sampling distribution (agreement within 1.4–4.8%, against a Monte Carlo error of about 1.1%). vars has no analytic standard errors at all, so statsmodels is the only software reference.

At horizon 0 the two forms differ structurally. Φ_0 = I is not estimated, so its standard errors are exactly zero. Ψ_0 = P depends on the estimated Σ, so its standard errors are not — except above the diagonal, where P is zero by construction.

julia> irf_stderr(m, 4)[1]                 # Φ₀ = I is not estimated

julia> round.(irf_stderr(m, 4; orth=true)[1]; digits=6)

TSAnalytics.lr_effects — Function
lr_effects(m::VARModel; orth=false) -> Matrix{Float64}

The long-run (total) effects Ψ_∞ = (I - Σ_j A_j)⁻¹, the limit of the cumulative responses; with orth=true, Ψ_∞ P.

Refuses an unstable VAR. The cumulative response only converges when every companion root is inside the unit circle. TSAnalytics.portmanteau_test — Function
portmanteau_test(m::VARModel; lags, adjusted=false) -> PortmanteauTest

Hosking's multivariate portmanteau test of the null that the VAR's residual vector is white noise up to lag lags:

Q_h = T Σ_{i=1}^{h} tr(C_i' C_0⁻¹ C_i C_0⁻¹),     C_i = T⁻¹ Σ_t u_t u_{t-i}'

asymptotically χ² with K²(h − p) degrees of freedom (Lütkepohl 2005, §4.4.1). adjusted=true weights lag i by T/(T − i), the small-sample form; every weight exceeds one, so the adjusted statistic is always the larger. [V] Both forms match vars::serial.test ("PT.asymptotic", "PT.adjusted") and statsmodels' test_whiteness(adjusted=…) to ≤ 4.2e-12 on seven fixtures.

C_0 is factorized once and each lag costs two triangular solves: tr(C_i' C_0⁻¹ C_i C_0⁻¹) = ‖L⁻¹ C_i L⁻ᵀ‖²_F with C_0 = LLᵀ.

Refusals. lags must exceed p, or the degrees of freedom are not positive — [V] vars runs anyway and reports df ≤ 0, while statsmodels refuses correctly. And lags must leave observations: statsmodels accepts lags = 300 on T = 198 and reports df = 1192.

TSAnalytics.es_test — Function

Edgerton-Shukur's small-sample F form of the bg_test statistic (Lütkepohl 2005, eq. 4.4.23), a Rao-type F approximation:

R²_r = 1 − |Σ̃_e| / |Σ̃_u|,     m = K·lags,   n = regressors per equation
r    = √((K²m² − 4) / (K² + m² − 5)),        q = Km/2 − 1
N    = T − n − m − (K − m + 1)/2
LMF  = (1 − (1 − R²_r)^{1/r}) / (1 − R²_r)^{1/r} · (N r − q) / (K m)

Cointegration

TSAnalytics.coint_test — Function
coint_test(Y; trend=:const, lags=nothing, autolag=:aic) -> CointTest

The Engle-Granger (1987) two-step test of the null of no cointegration: regress the first column of Y on the others (and the deterministic terms), then run an augmented Dickey-Fuller test with no deterministic terms on that regression's residual. A residual with no unit root means some linear combination of the series is stationary.

The first column is the dependent variable

The statistic is not symmetric in the ordering of the columns — swapping them gives a different number, and can give a different conclusion. Put the variable you would normalize the cointegrating relation on first.

trend sets the deterministic terms of the cointegrating regression: :none, :const (default), :trend (constant and linear trend) or :quadratic (constant, trend and trend²) — statsmodels' "n", "c", "ct", "ctt". (Unlike fit_var's deterministic, :trend here includes the constant; a trend without one is not a case MacKinnon tabulates.)

Lags: pass them explicitly to reproduce a reference

lags is the ADF regression's lag order — a maximum when autolag is :aic, :bic or :tstat, the exact order when autolag = nothing. The default is adf_test's own Schwert rule, ⌈12 (n/100)^{1/4}⌉, and the selection is adf_test's, so the package has one lag-selection implementation rather than two.

[V] At a fixed lag the statistic is unambiguous: statsmodels' coint and an Engle-Granger built by hand from R's lm and urca::ur.df agree to 1.8e-15. With each selecting its own lag they land on different orders on three of four fixtures — coint3_r1 gives −9.57 in R and −12.27 in Python. The test is not what they disagree about; the search is. An autolag-selected statistic will therefore not in general match either reference, and an explicit lags with autolag = nothing reproduces both.

Tables, and what is refused

p-values are MacKinnon's (1994) response surfaces, which cover N ≤ 6 series; critical values are MacKinnon (2010) at sample size n − 1, covering N ≤ 12 — both transcribed from statsmodels (BSD) and checked against urca's independent 1995-vintage tables, which agree to about 5e-4 on critical values and 2e-2 on p-values.

  • N between 7 and 12: the critical values are returned and pvalue throws, naming them.
  • N > 12: refused — nothing is tabulated.
  • trend = :none: refused. MacKinnon's no-constant critical values are for a single series only. [V] statsmodels returns a p-value with NaN critical values beside it here; no field of this result is ever NaN.
  • A single series: refused, naming adf_test. [V] statsmodels silently turns that into a plain ADF test and reports N = 1 critical values, which is not a cointegration test.

TSAnalytics.phillips_ouliaris_test — Function
phillips_ouliaris_test(Y; kind=:Pz, deterministic=:const, bandwidth=:short)
    -> PhillipsOuliarisTest

The Phillips & Ouliaris (1990) residual-based tests of the null of no cointegration among the columns of Y (2 to 6 series):

  • kind = :Pu — the variance ratio (their (12)): T ω̂₁₁.₂ / (T⁻¹ Σ û²), the long-run conditional variance of the first series given the others against the residual variance of the cointegrating regression. Like coint_test it depends on which series is first.
  • kind = :Pz — the multivariate trace statistic (their (14)): T tr(Ω̂ M_zz⁻¹), invariant to the normalization — no series is singled out. That is why it is the default.

Both are right-tailed: a large value rejects. Ω̂ is the Bartlett- weighted long-run covariance of the residuals of a first-order VAR in the levels, with bandwidth lags: :short is ⌊4 (T/100)^{1/4}⌋ and :long ⌊12 (T/100)^{1/4}⌋, with T = n − 1 (5 and 15 at n = 250) — urca's rules — or an integer; 0 gives the uncorrected statistic.

deterministic is not a detail

:none, :const or :trend (constant and trend) — urca's demean = "none" | "constant" | "trend", the paper's "standard", "demeaned" and "demeaned and detrended". The choice changes the answer qualitatively: [V] on coint2_trend.csv, whose cointegrating relation contains a trend, Pu is 3.19 with :none (no rejection at 10%), 50.24 with :const (rejects at 5%) and 170.0 with :trend (rejects at 1%). The default is :const; choose deliberately.

Pz with a deterministic term follows the paper, not urca

With a constant or trend, Phillips & Ouliaris build M_zz from the demeaned (or detrended) data (§3, remark (f)), which is what their Tables IVb and IVc were simulated under. [V] urca::ca.po uses the raw z'z there. The consequence is not cosmetic: urca's statistic is not invariant to adding a constant to the data (71.86 becomes 38.84 on coint2_yes.csv after adding 1000 to both series), and in 4000 simulations of independent random walks at n = 500 it rejected 0.25% of the time at the nominal 5% with a constant and 0% with a trend, against 4.3% and 4.2% for the paper's statistic. Pu, and Pz with :none, agree with urca to 1e-10.

No p-value

The paper tabulates quantiles only, at seven sizes from 15% to 1%; critical_values reports the 10%, 5% and 1% points and reject compares against them. pvalue(t) throws. [V] tseries::po.test reports 0.01 or 0.15 — the bounds of its table — as though they were p-values; nothing here is censored that way.

m > 6 is refused: the tables stop at five regressors.

TSAnalytics.johansen_test — Function
johansen_test(Y; lags, deterministic=:const) -> JohansenTest

Johansen's likelihood-ratio tests for the cointegration rank of the K series in Y: the trace statistic −T Σ_{i>r} log(1 − λᵢ) for H₀: rank ≤ r against rank ≤ K, and the maximum-eigenvalue statistic −T log(1 − λ_{r+1}) against rank = r + 1, for r = 0 … K−1, with λ the eigenvalues of the reduced-rank regression (see _johansen_rrr). [V] With the mappings below, urca::ca.jo and statsmodels' coint_johansen agree with each other and with this to ≤ 2.2e-11.

lags is required, and counts differenced lags — statsmodels' k_ar_diff. urca's K is lags + 1 (it counts the levels VAR's order). lags = 0 is refused: [V] statsmodels silently accepts it.

deterministic: five cases, one shared between the references

deterministicmeaningurca ecdetstatsmodels det_orderOsterwald-Lenum
:noneno deterministic term—-1Table 0
:constunrestricted constant (a drift in the data)"none"0Table 1
:const_restrictedconstant only inside the cointegrating relation"const"—Table 1*
:trendunrestricted constant and trend——Table 2
:trend_restrictedunrestricted constant, trend inside the relation"trend"—Table 2*

:const is the common default and is urca's ecdet = "none" despite the name: "none" there means no deterministic term inside the cointegrating relation, and an unrestricted constant is still fitted. A restricted term adds a row to β and an eigenvalue that is zero by construction; it is dropped from the test sequence. statsmodels' det_order = 1 detrends the data rather than fitting this package's :trend model, so the two are not compared.

Critical values: Osterwald-Lenum (1992), and which table

Each case uses the Osterwald-Lenum table its own decision table assigns (p. 466). Two consequences worth knowing:

  • :const uses Table 1, so it agrees with statsmodels' values, not urca's. urca's ecdet = "none" values (5% trace for p − r = 1, 2, 3: 8.18, 17.95, 31.52) are Osterwald-Lenum's Table 1.1*, the case where the model has an unrestricted constant but the data's constant lies in the cointegrating space only — a table the paper itself calls superfluous under Johansen's (1992) testing procedure. Table 1's 3.76, 15.41, 29.68 is the matching case, and statsmodels' independently simulated 3.84, 15.49, 29.80 agrees with it.
  • The smallest-block value near 3.84 under :const and :trend is the asymptotic theory, not a defect: the last block is χ²(1)-like in exactly those cases.

The paper tabulates p − r ≤ 11, so K ≤ 11; more is refused, never answered with NaN — [V] which statsmodels does silently for 13 series and for det_order = 2.

No p-value

pvalue(t) throws, naming critical_values and coint_rank. MacKinnon-Haug-Michelis (1999) response surfaces would give real p-values — something neither reference has — but they are a separate, paper-sourced task, and interpolating three tabulated quantiles into a pseudo-p-value is not done.

urca's spec = "transitory" reparameterizes the short-run part only; the eigenvalues and statistics are identical ([V] to 5e-12), so it is not a separate option here.

  • alpha: the matching adjustment coefficients S₀₁β, so that alpha[:, 1:r] * beta[:, 1:r]' is the rank-r impact matrix.
  • lags counts differenced lags (statsmodels' k_ar_diff; urca's K is lags + 1); nobs is the effective sample.

TSAnalytics.normalize_beta — Function
normalize_beta(t, r; scheme=:first_unit) -> Matrix{Float64}

The first r cointegrating vectors in a conventional normalization:

  • :first_unit — each column divided by its first element, so the first row is all ones. This is urca::ca.jo's V.
  • :identity — the leading r × r block made the identity, β_r (β_r[1:r, :])⁻¹. This is urca::cajorls's β, and what most applied work reports for r > 1.

Beyond the first relation the vectors are only identified up to a rotation, so an over-specified r still returns numbers; they mean nothing more than the rank you asserted.

VECM

TSAnalytics.fit_vecm — Function
fit_vecm(Y; lags, rank, deterministic=:const, method=:ml) -> VECMModel

Fit a vector error-correction model of cointegration rank rank with lags differenced lags (statsmodels' k_ar_diff; urca's K is lags + 1).

deterministic is johansen_test's five-value vocabulary, with the same meanings, so a rank chosen there and a model fitted here cannot silently refer to different specifications:

deterministicstatsmodelsurca
:none"n"—
:const"co" (constant outside the relation)ecdet = "none" + cajorls
:const_restricted"ci" (constant inside)ecdet = "const"
:trend"colo"—
:trend_restricted"coli"ecdet = "trend"

[V] "co" and "ci" are close — on coint2_yes, β₂ is −0.6673249 against −0.6673217 and the log-likelihoods differ by 0.022 — and they are different models.

Two estimators

  • method = :ml (default): Johansen's reduced-rank maximum likelihood — β from the same eigenproblem as johansen_test, then α, Γ and the deterministic terms by least squares given β. This is what all three references compute by default and what the Johansen rank test assumes. [V] urca::cajorls, statsmodels' VECM and tsDyn::VECM(estim = "ML") agree on β to ≤ 1e-14.
  • method = :twostep: Engle & Granger's two-step estimator — β from a static least-squares regression of the first series on the others (with any restricted deterministic term), then the error-correction regression. Consistent but not efficient, and a genuinely different estimate ([V] β = (1, −0.4931, −0.9655) against ML's (1, −0.4965, −0.9777) on coint3_r1); it matches tsDyn::VECM(estim = "2OLS"). Rank 1 only — [V] tsDyn warns and silently switches to ML when asked for more; this refuses instead.

Refusals

rank must be in 1 … K−1: rank 0 is a VAR in differences and rank K a stationary VAR in levels, and neither is a VECM. [V] statsmodels accepts both (returning an empty β for 0 and the identity for K), and also accepts k_ar_diff = 0, which is refused here too.

TSAnalytics.VECMModel — Type
VECMModel <: TimeSeriesModel

A fitted vector error-correction model, returned by fit_vecm:

ΔY_t = α β' Ỹ_{t-1} + Γ_1 ΔY_{t-1} + … + Γ_k ΔY_{t-k} + (unrestricted deterministic) + u_t

with Ỹ_{t-1} the lagged levels, augmented by a deterministic term when one is restricted to the cointegrating space.

  • alpha (K × r), beta (K₁ × r, K₁ = K + 1 when a term is restricted; its coefficient is the last row). beta is stored with its leading r × r block the identity — statsmodels' and cajorls' normalization — and alpha matches it, so alpha * beta' is the impact matrix. normalize_beta gives other forms.
  • gamma: lags matrices, each K × K; det_coef: K × n for the unrestricted deterministic terms (constant, then trend).
  • sigma_df (divisor T − q, q regressors per equation) and sigma_mle (divisor T).
  • stderr_alpha, stderr_gamma (K × K·lags), stderr_det: from the regression given β, with the ML Σ, as statsmodels computes them. stderr_beta: Lütkepohl's (2005, Prop. 7.6) asymptotic standard errors of the free elements of β, zero on the normalized block; nothing for method = :twostep, whose static regression gives none that are valid.
  • resid (T × K), loglik, nobs (T), lags (differenced lags), rank, deterministic, method.

TSAnalytics.var_rep — Function
var_rep(m::VECMModel) -> Vector{Matrix{Float64}}

The VECM written as a VAR in levels, lags + 1 coefficient matrices:

A₁ = I + α β' + Γ₁,    A_j = Γ_j − Γ_{j−1}  (j = 2 … lags),    A_{lags+1} = −Γ_lags

(β' restricted to its first K rows; a restricted deterministic term moves into the VAR's intercept or trend). This is what forecast and irf use — the VAR recursions of Stages 10.1 and 10.3, not a second implementation — and the test suite checks that the levels VAR reproduces the VECM's own residuals exactly.

[V] Matches vars::vec2var and statsmodels' var_rep.

The levels VAR has K − r unit roots by construction — that is what cointegration means — so it is not stable, and its long-run effects do not exist: lr_effects refuses a VECMModel.

Structural VAR

TSAnalytics.fit_svar — Function
fit_svar(m::VARModel; A=nothing, B=nothing, method=:scoring,
         maxiter=200, tol=1e-10) -> SVARModel

Estimate a structural VAR on the fitted reduced form m:

A u_t = B ε_t,    ε_t ~ (0, I_K),    so  Σ_u = A⁻¹ B B' A'⁻¹

Give A (an A-model, B = I), B (a B-model, A = I) or both (an AB-model), as K × K matrices with missing marking the free elements and numbers fixing the rest:

fit_svar(m; A = [1.0 0.0; missing 1.0], B = [missing 0.0; 0.0 missing])

missing, not NaN: NaN is refused by name. [V] statsmodels' marker is the string "E", and passing np.nan instead silently gives it an empty set of parameters and an opaque error.

Identification is checked first

Σ_u has K(K+1)/2 distinct elements, so at most that many parameters can be identified (Lütkepohl 2005, §9.1.2):

  • more free parameters than K(K+1)/2, or free parameters at the same position in A and B: refused before any optimization — [V] vars does the same; statsmodels fails deep inside with a singular-matrix error;
  • exactly K(K+1)/2: just-identified — A⁻¹B(A⁻¹B)' = Σ_u exactly, and there is nothing to test;
  • fewer: over-identified — the restrictions are testable, and lr_test carries Lütkepohl's likelihood-ratio statistic T(ln|Σ̃_r| − ln|Σ̃_u|) on K(K+1)/2 − nfree degrees of freedom.

The rank condition is checked too: a specification whose information matrix is singular is refused rather than handed to the optimizer.

A unit-diagonal `A` with `B = I` is over-identified

A = [1 0; missing 1] alone has one free parameter for a 2 × 2 Σ_u: it also forces both structural variances to one. It is the A-model vars and statsmodels are usually shown with, and [V] on var2_p1 vars itself rejects it (LR = 121.6 on 2 df). The just-identified recursive model is A = [1 0; missing 1] with a free diagonal B, or a lower-triangular free B — both reproduce the Cholesky factor exactly. (statsmodels reports the reduced-form log-likelihood as its SVAR llf whatever the restrictions, which hides this.)

Estimation

method = :scoring (default) is Amisano & Giannini's scoring algorithm — Newton steps with the expected information — which is what vars::SVAR(estmethod = "scoring") uses; :mle maximizes the same likelihood with _optimize's quasi-Newton method. Both start from a feasible point built from Σ_u. [V] vars' estmethod = "direct" stops short of the optimum (A₂₁ = −0.293750… against −0.293821) and R warns about it; it is not reproduced.

The likelihood is concentrated with the reduced form's degrees-of-freedom-adjusted Σ_u (m.sigma_df), which is what both references decompose — [V] their P P' is Σ_df. So loglik at a just-identified optimum is the Gaussian log-likelihood at Σ_df, which differs from loglikelihood(m) (computed at the ML Σ) by T/2 (ln|Σ_df| − ln|Σ_ml|); the LR test compares like with like.

Standard errors are the square roots of the inverse information matrix for the free parameters. Structural impulse responses and variance decompositions are irf(s, h) and fevd(s, h).

julia> using TSAnalytics, DelimitedFiles

julia> Y = readdlm(joinpath(dirname(pathof(TSAnalytics)), "..", "test",
                            "fixtures", "var", "var2_p1.csv"), ','; skipstart=1);

julia> m = fit_var(Y, 2);

julia> s = fit_svar(m; A = [1.0 0.0; missing 1.0], B = [missing 0.0; 0.0 missing]);

julia> s.lr_test === nothing          # just-identified
true

julia> s.P * s.P' ≈ m.sigma_df
true

julia> round(s.A[2, 1]; digits=6)
-0.293821

TSAnalytics.blanchard_quah — Function
blanchard_quah(m::VARModel) -> SVARModel

Blanchard & Quah's (1989) long-run identification: the structural shocks are orthogonal and the long-run impact matrix Ξ = (I − Σ_j A_j)⁻¹ B is lower triangular — the last shock has no permanent effect on the first variable, and so on. It is just-identified and has a closed form:

Ξ = chol(Ψ_∞ Σ_u Ψ_∞')ᴸ,    B = (I − Σ_j A_j) Ξ,    A = I

with Ψ_∞ = (I − Σ_j A_j)⁻¹ and Σ_u the degrees-of-freedom-adjusted residual covariance. B B' = Σ_u exactly, and lrim is lower triangular exactly — both asserted in the test suite with no reference involved. [V] B and lrim match vars::BQ; statsmodels has no equivalent.

An unstable VAR is refused: the long-run matrix Ψ_∞ does not exist when a companion root is on or outside the unit circle, which is the same refusal as lr_effects. vars::BQ inverts I − Σ A_j regardless.

julia> using TSAnalytics, DelimitedFiles

julia> Y = readdlm(joinpath(dirname(pathof(TSAnalytics)), "..", "test",
                            "fixtures", "var", "var2_p1.csv"), ','; skipstart=1);

julia> bq = blanchard_quah(fit_var(Y, 2));

julia> round.(bq.lrim; digits=4)
2×2 Matrix{Float64}:
 1.7871  0.0

TSAnalytics.SVARModel — Type
SVARModel <: TimeSeriesModel

A structural VAR, returned by fit_svar or blanchard_quah: the reduced form var, and the structural matrices in A u_t = B ε_t, ε_t ~ (0, I).

  • svar_type: :A, :B, :AB or :bq.
