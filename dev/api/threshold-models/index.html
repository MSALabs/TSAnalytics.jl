API: Threshold Models

Autoregressions whose coefficients depend on which side of a threshold a lagged value falls (Tong 1990): the self-exciting threshold AR (SETAR), with an abrupt switch, and the logistic smooth-transition AR (LSTAR), with a gradual one. thDelay = d means the threshold variable is y_{t−(d+1)}, and the low regime is z ≤ th, inclusive – both as in R's tsDyn, so its numbers can be checked directly.

SETAR

TSAnalytics.fit_setar — Function
fit_setar(y, m; thDelay=0, nthresh=1, threshold=nothing, trim=0.15,
          include=:const, mL=m, mH=m, mM=m, ML=nothing, MH=nothing,
          MM=nothing, grid=:full, max_iter=2) -> SETARModel

Self-exciting threshold autoregression, by conditional least squares:

y_t = c_L + Σ φ_{L,j} y_{t−j} + ε_t   if z_t ≤ γ
      c_H + Σ φ_{H,j} y_{t−j} + ε_t   if z_t >  γ,     z_t = y_{t−(thDelay+1)}

The low regime is z ≤ γ, inclusive. For each candidate threshold one dummy-expanded regression is fitted and the smallest sum of squares wins; the candidates are the sorted values of z, ties included, trimmed at trim (0.15). nthresh = 2 adds a middle regime by sequential search (the first threshold, then the second conditional on it, then the first again – max_iter alternations), not a joint grid.

thDelay counts from zero, as R's tsDyn: thDelay = 0 uses y_{t−1}. mL, mH, mM give each regime its own order; ML, MH, MM give it an explicit (possibly non-contiguous) set of lags. include is :const (one intercept per regime), :none, :trend or :both.

threshold fits at given threshold(s) instead of searching – pass it at full precision: a threshold typed back from a 12-digit print can move a boundary observation into the other regime and change the fit.

Standard errors: se uses the residual variance SSR / (rows − k). tsDyn divides by the full series length less the slope count, SSR / (n − p) – including observations the regression never used – and reports mse and AIC on n as well; those are kept in se_tsdyn (and tsdyn_ic) so its numbers can be reproduced exactly. The threshold has no standard error: its asymptotic distribution is non-standard (Hansen 2000), and a Gaussian one would mislead. tsDyn zero-pads it.

grid = :tsdyn reproduces tsDyn's candidate grid exactly, including its fractional-index truncation, which skips values – useful only to reproduce its selection tables. tsDyn uses trim defaults of 0.15 (setar), 0.1 (setarTest) and 0.1 (lstar's start grid); this package uses 0.15 throughout.

julia> using TSAnalytics, DelimitedFiles

julia> y = log10.(readdlm(TSAnalytics.LYNX, ','; skipstart=1)[:, 2]);

julia> m = fit_setar(y, 2; thDelay=1, warn=false);

julia> m.thresholds
1-element Vector{Float64}:
 3.3100557377508912

julia> round(m.ssr, digits=8)
4.34819128

julia> [count(==(r), m.regime) for r in 1:2]
2-element Vector{Int64}:
 78
 34

TSAnalytics.SETARModel — Type
SETARModel

A fitted SETAR model, from fit_setar: thresholds (full precision), coef/coefnames (const.L, phiL.1, …, const.H, …, with an M regime for two thresholds), ssr, nobs (regression rows), standard errors under the package's convention (se, residual variance SSR / (rows − k)) and under tsDyn's (se_tsdyn, SSR / (n − p)), the SSR profile over the candidate thresholds, and the regime of each row.

TSAnalytics.select_setar — Function
select_setar(y, m; thDelay=0:m-1, mL=1:m, mH=1:m, trim=0.15,
             criterion=:pooled_aic, grid=:full) -> NamedTuple

A grid search over threshold × delay × the two regimes' orders, as R's selectSETAR. criterion is :ssr, :aic (on the full series length, as tsDyn) or :pooled_aic (tsDyn's default: the two regimes fitted separately, each scored by its full Gaussian AIC with the variance counted, on a sample embedded at max(thDelay + 1, mL, mH) – so its rows depend on the orders being compared). Returns the best (thDelay, mL, mH, th, value) and the whole table, best first.

julia> using TSAnalytics, DelimitedFiles

julia> y = log10.(readdlm(TSAnalytics.LYNX, ','; skipstart=1)[:, 2]);

julia> s = select_setar(y, 2; thDelay=0:1);

julia> (s.best.thDelay, s.best.mL, s.best.mH, s.best.th)
(1, 2, 2, 3.3100557377508912)
source
TSAnalytics.tsdyn_ic — Function
tsdyn_ic(m::SETARModel) -> (mse, aic, bic)

tsDyn's figures, reproduced from the same SSR: everything on the full series length n, not the rows the regression used – mse = SSR/n, AIC = n log(mse) + 2k, BIC = n log(mse) + log(n) k, with k counting a searched threshold. aic and bic on the model use the regression rows instead.

LSTAR

TSAnalytics.fit_lstar — Function
fit_lstar(y, m; thDelay=0, trim=0.15, ngamma=40, nth=200, gamma_max=100.0) -> LSTARModel

Logistic smooth-transition autoregression,

ŷ_t = X_t' φ_L + (X_t' φ_H) · G(z_t),   G(z) = 1 / (1 + exp(−γ (z − c)))

with X_t = [1, y_{t−1}, …, y_{t−m}] and z_t = y_{t−(thDelay+1)}.

The form is additive: φ_H are increments, so the high regime's coefficients are φ_L + φ_H. (The convex form (1 − G) φ_L + G φ_H is a different model – on log10(lynx) its SSR at R's estimates is 67 times worse.) γ multiplies the raw z − c, not (z − c)/sd(z) as in much of the literature, so it is not comparable with a standardised slope.

The regime coefficients are profiled out by least squares; (γ, c) start from the best of an ngamma × nth grid (γ in 1:gamma_max, c over the trimmed range of z), then BFGS. The grid is not optional: the likelihood is nearly flat in γ, and without it the optimiser stays wherever it began. A γ at or past gamma_max is reported (gamma_at_bound) – the transition is then effectively abrupt, and fit_setar is the better model.

Standard errors are tsDyn's: vcov = 2 SSR / n · H⁻¹, H the Hessian of the SSR in all parameters, n the full series length. They are fragile for γ (its profile is nearly flat).

julia> using TSAnalytics, DelimitedFiles

julia> y = log10.(readdlm(TSAnalytics.LYNX, ','; skipstart=1)[:, 2]);

julia> m = fit_lstar(y, 2; thDelay=1);

julia> round(m.ssr, digits=5)
4.33764

julia> m.gamma_at_bound
false
source
TSAnalytics.LSTARModel — Type
LSTARModel

A fitted LSTAR model, from fit_lstar: phiL and phiH (the high coefficients are increments: the high regime's levels are phiL + phiH), gamma, th, ssr, the transition G per row, and standard errors (tsDyn's convention). gamma_at_bound records a slope that ran to the start grid's maximum.

Testing for a threshold

TSAnalytics.setar_test — Function
setar_test(y, m; thDelay=0:m-1, trim=0.15, nboot=1000, rng=Random.default_rng()) -> ThresholdTest

Hansen's (1999) bootstrap tests: linear AR(m) against one and two thresholds, and one threshold against two. F_ij = n (S_i − S_j)/S_j, n the regression rows, each SETAR searched over thDelay. The null distribution is non-standard, so the p-values are by bootstrap only: residuals resampled under the null model, every statistic recomputed. tsDyn's default of 10 replications is far too few to be stable; the default here is 1000.

julia> using TSAnalytics, DelimitedFiles

julia> y = log10.(readdlm(TSAnalytics.LYNX, ','; skipstart=1)[:, 2]);

julia> t = setar_test(y, 2; thDelay=0:1, nboot=10);

julia> round.(t.F, digits=4)
3-element Vector{Float64}:
 36.9468
 46.5898
  7.251
source
TSAnalytics.ThresholdTest — Type
ThresholdTest <: HypothesisTest

Hansen's (1999) tests of linearity against SETAR, from setar_test: the sums of squares of the linear AR and the one- and two-threshold SETARs, the statistics F_ij = n (S_i − S_j) / S_j with n = rows, bootstrap p-values and critical values, and the bootstrap draws themselves (boot, nboot × 3). plot(t) draws their distributions.
