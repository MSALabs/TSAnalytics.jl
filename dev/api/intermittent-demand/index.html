API: Intermittent Demand

Series that are mostly zero, with occasional demands: Croston's method and its bias-corrected (SBA) and optimised forms, TSB, the temporal-aggregation methods ADIDA and IMAPA, and the ADI/CV² classification that chooses between them. Every point forecast agrees with statsforecast exactly, and classical Croston with R's forecast::croston to all 17 digits. No method here has prediction intervals, because no reference computes any.

Methods

TSAnalytics.croston — Function
croston(y; method=:classic, alpha=0.1) -> IntermittentModel

Croston's (1972) method for intermittent demand: simple exponential smoothing of the non-zero demands, divided by the same smoothing of the intervals between them, a flat forecast of demand per period.

  • :classic: both smoothed with alpha (0.1, the value both references hardcode). Identical to R's forecast::croston and statsforecast's CrostonClassic, to all 17 digits.
  • :sba: Syntetos & Boylan's (2005) bias correction, the classic forecast times 1 − alpha/2. statsforecast multiplies by a literal 0.95, which is 1 − alpha/2 only at its hardcoded alpha = 0.1; here the factor follows alpha. (Syntetos & Boylan's later SBJ factor 1 − alpha/(2 − alpha) is not offered.) A single observation is refused: there is no bias to correct.
  • :optimized: each of the two smoothings gets its own alpha, chosen by a golden-section search for the smallest one-step squared error within [0.1, 0.3] – statsforecast's CrostonOptimized. The bound binds often (on two of four test series one alpha ends at it), so this is a restricted search, not a free optimum.

Simple exponential smoothing starts from the first value, as in both references – the reason they agree exactly. Refused: negative values, and a single demand at the first period followed only by zeros, for which both references return the demand itself (5 for [5, 0, …, 0], against an empirical rate of 0.5). An all-zero series forecasts zero.

julia> using TSAnalytics

julia> m = croston([0, 0, 3, 0, 0, 0, 2, 0, 4, 0]);

julia> round(m.forecast, digits = 6), m.method
(1.006689, :classic)

julia> forecast(m, 3).point == fill(m.forecast, 3)
true

TSAnalytics.tsb — Function
tsb(y; alpha_d, alpha_p) -> IntermittentModel

Teunter, Syntetos & Babai's (2011) method: the probability of a demand in a period, smoothed over every period with alpha_p, times the size of a demand, smoothed over the non-zero demands with alpha_d. Unlike Croston there is no interval – so the forecast decays during a long run of zeros instead of waiting for the next demand, which is what makes it suited to items going obsolete. Both constants are required: statsforecast's docstring says they are optimised as in its optimised Croston, but its code takes them as given, and so does this.

julia> using TSAnalytics

julia> round(tsb([0, 0, 3, 0, 0, 0, 2, 0, 4, 0]; alpha_d = 0.2, alpha_p = 0.2).forecast, digits = 6)
0.925203
source
TSAnalytics.adida — Function
adida(y; aggregation=nothing) -> IntermittentModel

The aggregate–disaggregate approach (Nikolopoulos et al. 2011): sum the series into non-overlapping buckets as wide as the mean interval between demands (round of it, half to even), forecast the bucket sums by simple exponential smoothing with alpha chosen in [0.1, 0.3], and divide by the width. Buckets are aligned to the end of the series; an incomplete bucket at the start is dropped. aggregation fixes the width instead.

The rounding rule matters when the mean interval is exactly a half: statsforecast rounds half to even for the forecast but half away from zero for its fitted values, so the same series gets two widths – on a series with mean interval 2.5, widths 2 and 3 give forecasts 20% apart. This uses half to even throughout, matching statsforecast's forecast.

source
TSAnalytics.imapa — Function
imapa(y) -> IntermittentModel

Multiple temporal aggregation (Petropoulos & Kourentzes 2015): the adida forecast at every bucket width from 1 to the rounded mean interval, averaged. When the mean interval rounds to 1 it is ADIDA at width 1, exactly.

source
TSAnalytics.IntermittentModel — Type
IntermittentModel

A fitted intermittent-demand model, from croston, tsb, adida or imapa: the method, the flat point forecast, the smoothed demand_level and interval_level (Croston; the probability_level for TSB), the smoothing constants used, the aggregation level (ADIDA/IMAPA), the in-sample fitted one-step forecasts where they are computed (nothing otherwise), and the adi_cv2 classification of the series.

source
TSAnalytics.IntermittentForecast — Type
IntermittentForecast

Point forecasts from an IntermittentModel – flat in the horizon – and nothing else. There are no prediction intervals: neither R's forecast::croston nor statsforecast computes any (one passes PI = FALSE, the other raises unless wrapped in conformal intervals, which give negative lower bounds on a count series), and a Forecast with invented ones would be worse than none.

The decomposition and the classification

TSAnalytics.demand_intervals — Function
demand_intervals(y) -> DemandIntervals

The decomposition Croston's method smooths: the non-zero demands and the intervals between them. The intervals sum to the position of the last demand, and the demands to the series total.

julia> using TSAnalytics

julia> d = demand_intervals([0, 0, 3, 0, 2, 0]);

julia> d.demands, d.intervals
([3.0, 2.0], [3, 2])
source
TSAnalytics.DemandIntervals — Type
DemandIntervals

An intermittent series split into its non-zero demands, the intervals between them (the first counts from the start of the series) and the positions of the demands, built by demand_intervals.

source
TSAnalytics.adi_cv2 — Function
adi_cv2(y; adi_cutoff=1.32, cv2_cutoff=0.49) -> ADICV2Result

Classify an intermittent series by its average demand interval (ADI, the mean of the intervals demand_intervals returns) and the squared coefficient of variation of its non-zero demands (CV², sample standard deviation). Above either cutoff SBA is recommended, otherwise Croston: the rule of R's tsintermittent::idclass, whose cutoffs 1.32 and 0.49 come from Syntetos, Boylan & Croston (2005). Neither forecast nor statsforecast classifies at all.

The four quadrant names – :smooth (both below), :intermittent (ADI above), :erratic (CV² above), :lumpy (both above) – are the paper's vocabulary, not idclass's, which decides only SBA versus Croston.

julia> using TSAnalytics

julia> c = adi_cv2([0, 0, 3, 0, 0, 0, 2, 0, 4, 0]);

julia> round(c.adi, digits = 4), c.method, c.quadrant
(3.0, :sba, :intermittent)
source
TSAnalytics.ADICV2Result — Type
ADICV2Result

The Syntetos–Boylan–Croston classification of an intermittent series, from adi_cv2: the average demand interval adi, the squared coefficient of variation of the non-zero demands cv2, the recommended method (:sba or :croston), and the quadrant.
